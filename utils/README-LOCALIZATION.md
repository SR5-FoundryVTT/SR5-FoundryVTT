# Localization workflow

Locale sources live in `src/locale/<language>/`. Every supported language contains the same twelve feature-domain JSON
files. English is the canonical key tree; translations must keep the same keys in the same modules.

Foundry loads `dist/locale/<language>/config.json`. These files are generated by the normal build and watch tasks and
must not be edited directly.

## Commands

```bash
npm run locale:check
npm run locale:check -- fr
npm run locale:build
npm run locale:base-usage
```

- `locale:check` rejects missing or extra modules and keys, duplicate merge paths, empty strings, `[MISSING]` markers,
  type differences, moved key ownership, and changed placeholders or HTML tag structure.
- `locale:build` validates all sources and assembles one `config.json` for each language.
- `locale:base-usage` reports English keys that do not appear literally in source code. Dynamically constructed keys can
  be false positives.

## Adding and changing strings

Add a new key to the appropriate English domain and to the same domain in German, French, Korean, and Brazilian
Portuguese. Keep an entire `SR5.<namespace>` in one domain file. Root-level `CONTROLS`, `SETTINGS`, and `TYPES` belong
in `system.json`; generic scalar `SR5` entries belong in `common.json`.

Preserve `{placeholder}` names and HTML tag structure exactly. Existing English-equivalent proper names and technical
terms are valid translations, but empty values and temporary missing markers are not.
